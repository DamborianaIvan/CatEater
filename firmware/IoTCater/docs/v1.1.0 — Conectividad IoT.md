## v1.1.0 — Conectividad IoT

La versión `v1.1.0` incorpora la conectividad del firmware con el ecosistema CatFeeder.

### Conectividad WiFi

El firmware utiliza `WiFiService` para gestionar:

- Conexión inicial a la red WiFi.
- Detección del estado de conexión.
- Reconexión automática.
- Obtención de IP, MAC y RSSI.
- Detección de transiciones hacia un estado conectado.

Cuando el dispositivo establece conexión, se ejecuta el flujo de inicialización asociado a la conectividad.

### Cliente HTTP

Se incorporó `HttpClient` como capa de transporte para las comunicaciones externas.

Actualmente soporta:

- `GET`
- `POST`
- HTTP
- HTTPS
- Headers personalizados
- Timeout configurable
- Respuestas mediante `HttpResponse`

La selección entre HTTP y HTTPS se realiza automáticamente a partir de la URL.

### Cliente de API

`ApiClient` encapsula el contrato entre el firmware y el backend.

Actualmente implementa:

```text
POST /feeders/register
```

La petición utiliza API Key mediante el header:

```text
x-api-key
```

y envía la información necesaria para registrar el dispositivo.

### Registro del dispositivo

El dispositivo informa:

- `feederId`
- `feederName`

El resultado de la operación se traduce a `RegistrationResult`, evitando que las capas superiores tengan que trabajar directamente con códigos HTTP.

Resultados contemplados:

| HTTP | Resultado |
|---:|---|
| 201 | `Registered` |
| 409 | `AlreadyRegistered` |
| 401 | `Unauthorized` |
| 400 | `InvalidData` |
| 500 | `ServerError` |
| Error de conexión | `ConnectionError` |

### Flujo de conectividad

El flujo actual es:

```text
ESP8266
   ↓
WiFiService
   ↓
Conexión WiFi
   ↓
DeviceInfo
   ↓
ApiClient
   ↓
HttpClient
   ↓
Backend
   ↓
Registro del dispositivo
```

El registro se ejecuta cuando el firmware detecta la transición hacia un estado WiFi conectado.

### Estado

`v1.1.0` deja implementada y validada la comunicación básica entre el firmware y el backend.

La prueba manual de desconexión y posterior reconexión WiFi queda pendiente de ejecución, aunque el soporte necesario para detectar la transición y volver a ejecutar el flujo ya se encuentra implementado.
